# Personal Mac access — review and validation

The owner requested account-free public-playlist import and suggestions for one Mac, a simpler import dialog, and corrected browser copy. The account remains available under Library for existing cloud playlist links. The browser continues to use its existing owner-authenticated API path. No cloud library migration, deletion or automatic repair is introduced.

## Security and behavior review

The personal device secret is generated locally from 32 random bytes, kept in an origin-scoped Keychain item and never placed in the app bundle, URL, logs or error messages. The server stores a SHA-256 digest and compares fixed-size digests in constant time. The Mac uses the credential only for `GET /api/youtube/playlist` and `POST /api/youtube/suggestions`; malformed, wrong and unavailable credentials fail closed, and the same credential does not authorize cloud playlist-link endpoints. The existing browser owner, cookie and CSRF checks remain in place. The native transport disables cookies, rejects redirects, bounds responses and checks cancellation before returning.

Personal suggestions send a playlist ID and at most five bounded track titles, channels and durations to the service to generate YouTube searches. They do not send track descriptions, tags, local queue or history. Personal results are cached only in the app's bounded in-memory cache; the personal route neither reads nor writes the server suggestion result cache. The server still transiently processes the request and sends derived search terms to YouTube. The server rate limiter is process-local and is not a global quota guarantee.

The import sheet no longer presents account controls. The previous sheet lifecycle fix and in-progress cancellation remain, and late responses are fenced before local persistence. The Mac still permits explicitly signing in through Library → Account for cloud links. The webpage now states that current browser imports require the configured owner's sign-in, and the public Mac download manifest remains null.

## Validation

- Isolated macOS arm64 host with a synthetic bundle ID/callback: **274 XCTest cases executed, 272 passed, two existing skips, zero failures**. The isolated callback registration was adapted to the synthetic ID; six separate offline checks validate the real checked-in callback configuration. Tests include successful signed-out playlist import and persistence into a disposable library, personal suggestions and cache scoping, Unicode request bounds, late-response cancellation and import-sheet transitions. File-panel completion was simulated, not physically clicked. [Native log](../../../build/tubeshuffle-personal-validation-5k2wjy3m/native-final-full.log).
- Web: **541 passed, two skipped**; seven loopback HTTP integration tests passed, including the actual Next route/proxy with a simulated provider. TypeScript and production build passed with local font fixtures. Lint reported no errors and two pre-existing warnings. Tests used an allowlisted environment and a loopback network guard; the guard is not an OS firewall. [Web test log](../../../build/tubeshuffle-personal-validation-5k2wjy3m/web-full-final.log), [HTTP log](../../../build/tubeshuffle-personal-validation-5k2wjy3m/http-final.log), [build log](../../../build/tubeshuffle-personal-validation-5k2wjy3m/web-build-final.log), [lint](../../../build/tubeshuffle-personal-validation-5k2wjy3m/lint-final.log).
- Both the earlier committed image configuration and the newer configuration on main were built and tested; the latter is preserved unchanged for the eventual merge. No real browser profile, real library, actual personal playlist, live login, production migration or schema change was used in tests.

This is a focused self-review and synthetic validation, not proof of production security or live-service availability. Signed-Keychain behavior was previously exercised across launches using a separate synthetic service and targeted cleanup; actual personal pairing and provider playback require their own observed result. The YouTube minimized/hidden playback policy and public-release gates remain open.
