# Simulated P2 HTTP integration

Run `node --test tests/integration/p2-http.test.mjs` with dependencies installed. A disposable copy of the app runs via Next dev on loopback, with a synthetic Supabase Auth/PostgREST provider and synthetic YouTube endpoint. Real Supabase JS/SSR clients and actual HTTP route handlers are used; provider responses and credentials are entirely synthetic. A Node preload guard intercepts global fetch and net.Socket.connect in instrumented child processes, rejects non-loopback destinations on those paths, and redirects the hard-coded Google API origin to the local provider. It is not an OS network sandbox: native code, uninstrumented processes, other APIs, and redirects may bypass it. Run only in an environment where external network access is independently restricted if isolation is required. The test releases a reserved loopback port before Next binds it, so another process can claim it in the meantime; the port is not isolated from other local processes. Cleanup is best effort: shutdown is bounded, and the temporary app directory is retained if Next's exit cannot be confirmed. Abrupt termination can also leave processes, listeners or temporary files behind.

The fake provider recognizes exact synthetic HS256-shaped token strings and does not cryptographically verify JWT signatures; it is not Supabase, Postgres, RLS, Google OAuth, or YouTube. These tests make no live security, deployment, quota, or RLS claims. The test does not connect to a project or use real credentials. Tests for live RLS, actual provider expiry/revocation, production builds and deployment remain separate gates.
