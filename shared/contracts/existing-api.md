# Existing YouTube proxy wire contract (current implementation)

This describes the current unauthenticated server handlers, not the proposed owner/authenticated API. Requests use a server-side `YOUTUBE_API_KEY`; clients do not send it. Examples in `../fixtures/existing-api.json` are mocked handler outputs, not live YouTube guarantees. The upstream error envelope is `{ "error": { "code": number, "message": string } }`; the proxy's own error envelope is `{ "error": string }`. They are not interchangeable. The separate proposed authenticated API may have different envelopes and semantics.

## GET /api/youtube/playlist

Only `list` and `playlistId` query keys are accepted. The first `list` wins over the first `playlistId`, even if empty; trim it and require `/^[A-Za-z0-9_-]{10,80}$/`. Unknown keys, missing/empty or invalid IDs return 400. The server key is checked before query validation. The handler requests playlist metadata, then `playlistItems` pages of 50. It permits 100 pages; a continuation after page 100 returns 422 (no partial result). It filters missing IDs and titles exactly equal to `Deleted video` or `Private video`, retains duplicate IDs, and assigns consecutive positions after filtering. It then requests details in batches of 50 occurrences, not unique IDs. `videoCount` is the upstream item count when present, otherwise the filtered count; it need not equal `videos.length`.

200 body fields (all fields in each list are present unless marked optional):

* Playlist: `id`, `title` strings; `description`, `thumbnail`, `channelTitle` string **or null**; `videoCount` number; `videos` array. Missing title defaults to `Untitled Playlist`. Thumbnail prefers high then default, otherwise null.
* Each video: `id`, `title`, `channelTitle`, `thumbnail` strings; `duration`, `position` numbers. Defaults are `Untitled`, `Unknown`, empty thumbnail, and zero duration. `duration` is seconds. Optional `viewCount`, `likeCount` numbers; `description`, `categoryId`, `publishedAt` strings; `tags` array of strings. Absent/undefined values are omitted, not explicit null by design; upstream malformed values are not schema-validated. Dates are copied, not normalized. Counts are parsed with JS `parseInt` and are not bounded to safe integers; non-finite numeric values serialize as null. If details are missing the optional properties are omitted. Thumbnail prefers high then default.

## POST /api/youtube/suggestions

Body is JSON; no content-type validation. Unknown properties are ignored. `playlistId` must be a string, trimmed and nonempty, with at most 120 UTF-16 code units. `seeds` must contain at least one object with string `title` and `channelTitle` (empty strings are allowed); invalid entries are filtered, then only the first 40 retained. Each retained title is sliced to 180 code units, channelTitle to 120, optional string `description` to 600, `categoryId` to 20; optional `tags` is filtered to strings, first 12, each sliced to 60; optional numeric `duration` is passed through. `playlistTitle` is optional string sliced to 160, `refreshToken` optional string sliced to 80. `excludeVideoIds` is an optional array filtered to strings then sliced to 5,000; no ID validation or deduplication occurs during validation. `dateKey` is a nonempty trimmed string without date-format validation, otherwise current UTC date `YYYY-MM-DD`.

Only a declared `Content-Length` parsed by `parseInt` and greater than 128,000 triggers 413. Missing, malformed, understated, or negative headers are not an actual body byte limit; the handler reads JSON without independently measuring bytes. Key validation precedes this check, then JSON parsing and body validation. After validation a process-local 24-hour memory cache is consulted before a process-local per-client limit of 30 cache misses per hour (first `x-forwarded-for` entry, else `x-real-ip`, else `unknown`). Cache identity uses playlistId, dateKey, title/channel/tags of seeds, only exclusion count/first/last and refreshToken; it does not include all request fields. Cache hits retain the original generatedAt and quotaCost. Neither mechanism is a durable or distributed guarantee.

Up to four distinct generated searches are made, stopping only after at least two searches and nine distinct non-excluded candidates; at most one details call covers the first 50 candidate IDs. Results are ranked, de-duplicated, excluded, then select up to five; an initial duration preference is followed by a fallback that may include out-of-range durations. `quotaCost` is `100 * searches + detailsCalls`, not a fixed constant. Empty searches can run all four and require no details call. Search content and ranking depend on seeds, upstream and current implementation.

200 body: required `playlistId`, `generatedAt`, `dateKey`, `query` strings, `quotaCost` number, `suggestions` array. `generatedAt` is the server's ISO timestamp at generation, not necessarily dateKey. Each suggestion has required string `id`, `youtubeId` (same value), `title`, `channelTitle`, `thumbnail`, `url`, `reason`, `query`; required numeric `duration` in seconds; optional string `publishedAt` and numeric `viewCount` omitted if undefined. Defaults are `Untitled suggestion`, `YouTube`, empty thumbnail and zero duration. Thumbnail preference is high, medium, default. Published date prefers details then search snippet; counts use JS `parseInt` and non-finite numbers serialize as null. Missing details do not prevent a suggestion.

## Errors and boundaries

Both handlers return 500 `Server configuration error` for missing key; unexpected exceptions including network failures and invalid upstream JSON return 500 `Unexpected server error`. Upstream JSON is parsed before status handling; error `code` takes precedence over HTTP status. Playlist maps upstream 404 to 404 `Playlist not found`, 403 to 502 `YouTube API request rejected`, 429 to 429 `YouTube API rate limit exceeded`, other non-OK to 502 `YouTube API request failed`; missing playlist item is also 404. Suggestions maps 403 to 502 `YouTube API request rejected or quota exceeded`, 429 to 429 `YouTube API rate limit exceeded`, other non-OK to 502 with upstream error message or `YouTube API request failed` (including 404). Local suggestions limit returns 429 `Daily suggestions are temporarily rate limited`.

Playlist validation errors are 400 `Unsupported query parameter: <key>`, `Missing required query parameter: list`, or `Invalid playlist id format`; its page cap returns 422 `Playlist exceeds supported import size`. Suggestions returns 413 `Suggestions request is too large`, 400 `Invalid JSON request body`, `Invalid suggestions request body`, `Missing or invalid playlist id`, or `At least one suggestion seed is required`. Request order and actual implementation control precedence. These examples do not claim malformed upstream data always conforms to declared DTO types or that live API behavior has been tested.
