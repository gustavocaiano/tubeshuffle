# P1 contracts

These are design artifacts, not implemented endpoints. [Existing API](existing-api.md) describes current unauthenticated handlers and their [examples](../fixtures/existing-api.json); [owner API](owner-api.md) and [transfer v1](transfer-v1.md) are proposed and must not be mistaken for deployed behavior. [Shuffle v1](shuffle-v1.md) specifies the current algorithms and injected draws, with [Smart vectors](../fixtures/smart.json). [Owner vectors](../fixtures/owner-api-proposed.json) and [transfer vectors](../fixtures/transfer-v1.json) specify proposed behavior, not implemented systems. The transfer fixture's top-level snapshot is legacy input, not a new export; its fixture-only `vectors` key is not wire data, and orphan history is omitted and reported. Fixtures contain synthetic public identifiers, never credentials. JSON is UTF-8 and consumable without TypeScript.

Smart vectors exercise the current web implementation using injected draws rather than prescribing a seeded RNG. For the `orders` vectors, input is exactly the first `length` items of the cyclic `tracks` array; each item is copied and augmented with `occurrence` equal to its zero-based input index, even when IDs repeat. `random` is supplied once for each Math.random call, in order, and exhaustion is a test failure. Expected output lists input indices, not video IDs. The 9/10 and 23/24 cases straddle wave group sizes 1/2/3. See the shuffle specification for all vector shapes, draw rules and classifier details. Swift execution and parity remain unverified.
